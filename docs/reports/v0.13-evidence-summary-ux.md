# v0.13 Evidence Summary UX

Date: 2026-05-27
Branch: `codex/v013-evidence-summary-ux`

## Scope

This slice adds a local evidence navigator for QA-Z run artifacts. The goal is
to make the first post-run read obvious: verdict, status, top risks, evidence
paths, repair prompt path, verify report path, and next commands.

This is product UX and reliability work. It is not a marketing, release, or
package-publishing slice.

## What changed

- Added `qa-z summary --from-run latest`.
- Added `qa-z summary --json` with a stable top-level schema:
  `status`, `verdict`, `run_dir`, `evidence`, `top_findings`,
  `repair_prompt`, `verify_report`, `next_actions`, and `warnings`.
- Added `qa-z summary --markdown` and `--output` for local review artifacts.
- Added missing-run and stale-latest behavior that returns guidance instead of
  crashing.
- Added evidence detection for fast summaries, sibling deep summaries, review
  packets, GitHub summary artifacts, guard verdicts, repair prompts, and verify
  reports.
- Added deterministic next actions for missing deep evidence, missing repair
  prompts, and missing verification.

## Product value

Before this slice, users had to know whether to open `review/review.md`,
`guard/verdict.json`, `github-summary.md`, `repair/prompt.md`, or
`verify/report.md` first. The new command gives one short local answer and then
points to the deeper artifact that owns the next step.

## Compatibility

The implementation reads existing artifact shapes. It does not change fast,
deep, review, repair, guard, GitHub summary, or verification artifact producers.
It treats missing companion evidence as a warning and preserves the existing
artifact contracts.
