# QA-Z v0.10.0-beta Rollback/Yank Policy

Policy date: 2026-05-17
Policy type: rollback/yank policy packet, not release execution.

This is policy-only. It defines release-path-specific rollback, yank, delete,
deprecate, restore, and incident-decision requirements before any future
release execution packet can run.

## Purpose

The purpose of this packet is to keep rollback/yank planning explicit before a
release owner approves a tag, GitHub Release, package publish, deploy, package
yank, package delete, or version execution path.

This packet does not choose a release path, does not approve credentials, and
does not perform a release action.

## Policy Scope

This policy covers the release paths that can create external state or public
user impact:

- GitHub prerelease and tag paths;
- TestPyPI and PyPI publish paths;
- npm publish paths;
- GitHub Packages publish paths;
- docs site / hosted demo deploy paths;
- metadata-only version PR paths.

It does not cover target-repository remediation, production credentials,
registry login, package upload, package yank, package delete, tag deletion,
GitHub Release deletion, deploy execution, or incident execution.

- stop condition for not executing rollback/yank;
- proof links after any approved action.

## What Local Rollback Cannot Prove

Local git revert or local artifact deletion does not prove registry rollback.

A local revert can change source files in this repository, but it does not prove
that a package registry, GitHub Release, Git tag, package index, deploy
platform, cache, installer, or downstream environment stopped serving a
published artifact. A local cleanup can remove `dist/`, `build/`, or cache
folders, but it does not prove that an uploaded package, yanked release,
deleted package, deprecated npm package, deleted tag, edited GitHub Release, or
rolled-back deployment changed externally.

External state needs external proof from the selected service.

## Incident / Communication Steps

A later incident packet must not assume a local undo is enough. It must record:

1. The external object affected: tag, release, package URL/version, package
   scope, deployment ID, or domain.
2. The user impact: install breakage, advisory exposure, wrong version,
   unavailable artifact, stale docs, or cache behavior.
3. The selected official policy source and exact policy check timestamp.
4. The release owner and incident owner.
5. The approved action: edit, supersede, yank, delete, deprecate, restore,
   redeploy, or no action.
6. The communication target: maintainers, users, downstream consumers, registry
   support, or GitHub issue/release notes.
7. The post-action proof: registry page/API, release page, tag ref, deployment
   status, public raw proof, and validation rerun.

## Required Proof Before Execution

Before any release execution or rollback/yank action, the release owner must
have:

- release-owner approval;
- selected path and exact release SHA;
- final release-execution-time SHA proof;
- package smoke proof when package artifacts are involved;
- advisory decision proof;
- credentials or permission proof without printing secrets;
- official policy checked at execution time;
- rollback/yank/deprecate/delete/restore decision;
- incident communication plan;
- generated artifact cleanup status;
- explicit non-actions for anything not approved.
