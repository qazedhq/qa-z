# v0.11 Doctor & Environment Diagnostics

## Purpose

Make `qa-z doctor` useful as the first-line diagnostic for installed-package,
source-checkout, GitHub Actions, and project-configuration failures.

This is a product reliability slice. It is not a release, marketing, package
publish, or external posting slice.

## What changed

- Added a stable doctor result model with top-level `status`, `version`,
  `checks`, `warnings`, `errors`, `suggestions`, and `next_actions`.
- Added per-check diagnostics for runtime, package version, invocation,
  install-mode hints, project root, git, `qa-z.yaml`, profile shape, Semgrep,
  packaged auth-bug resources, `.qa-z` writeability, and GitHub Actions.
- Reworked human output into short PASS/WARN/FAIL lines with numbered next
  actions.
- Preserved legacy config `warnings`, `errors`, and `suggestions` so existing
  config-validation users keep their machine-readable issue shape.
- Added focused tests for environment diagnostics, JSON schema stability, human
  next actions, docs truth, and compatibility with existing init/config doctor
  tests.

## Product value

Operators can now run one local command to answer:

- Which QA-Z package version and module path am I running?
- Is this a source checkout, editable install, installed wheel/sdist, venv,
  pipx-like path, or GitHub Actions environment?
- Is `qa-z.yaml` present and valid?
- Are git, Semgrep, packaged demo resources, and `.qa-z` writes available?
- Are GitHub Actions summary/SARIF/comment expectations explicit?

## No-release boundary

- no PyPI/TestPyPI upload
- no `twine upload`
- no version bump
- no tag, GitHub Release, or deploy
- no live PyPI install claim
- no generated artifacts committed
- no external posting or bot comment

Production PyPI is not published. The current active install path remains the
GitHub source/tag install path until a separate release-owner publish packet is
approved, executed, and proven.
