# v0.15 GitHub Action Runtime Hardening

## Purpose

Make QA-Z GitHub Action failures easier to diagnose without expanding default
permissions or enabling bot behavior by default.

## What Changed

- The guard composite action now validates `profile`, `deep`, `adapter`,
  `fail-on-risk`, `upload-sarif`, and optional `from-run` before installing
  QA-Z or running the guard.
- Invalid action inputs produce a GitHub Actions error with the bad input,
  supported values, suggested fix, and `docs/github-action.md` troubleshooting
  link.
- The full `.github/actions/qa-z` reusable action now validates `adapter`,
  `run-dir`, and `upload-sarif`, and keeps SARIF upload disabled unless
  `upload-sarif: "true"` is set.
- The optional PR comment template validates `QA_Z_POST_PR_COMMENT` before
  running the gate.
- GitHub summary output now includes a conservative verdict, top blocked
  reason, artifact existence markers, SARIF permission guidance, and next
  commands for `qa-z summary`, `qa-z repair-prompt`, and `qa-z verify`.
- Action fallback summaries now point to the missing run, review packet, repair
  prompt, and SARIF paths instead of leaving operators with a blank summary.

## Permission Boundary

The minimal PR gate remains:

```yaml
permissions:
  contents: read
  actions: read
```

`security-events: write` is only needed when SARIF upload is explicitly enabled.
PR comments remain opt-in through the separate comment template and require a
separate `pull-requests: write` review.
