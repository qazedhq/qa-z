# QA-Z v0.10.0-beta Release Execution Checklist

Checklist date: 2026-05-17
Checklist type: release-owner execution checklist, not release execution.

This checklist does not execute a release. It consolidates the required
release-owner approval fields, blocker states, proof links, and non-actions that
must be reviewed before any future release execution packet can run.

## Purpose

The purpose of this checklist is to give the release owner one pre-execution
view of the `v0.10.0-beta` gates. It connects readiness, release decision,
version policy, advisory, historical exact-SHA proof, final SHA proof protocol,
and package publish planning without approving any release action.

This checklist is not a tag plan, GitHub Release plan, package upload packet,
deploy packet, version metadata PR, credential checklist, or final proof packet.

## Pre-execution Gate Order

1. Confirm release-owner approval and selected release path.
2. Confirm version/package metadata execution decision.
3. Freeze the exact release SHA.
4. Generate final release-execution-time SHA proof after freeze.
5. Confirm remote CI proof and Public Raw Hygiene proof for the frozen SHA.
6. Confirm exact-SHA public raw file proof for release-critical files.
7. Confirm tool-equipped twine/pipx/uvx smoke in a no-upload environment.
8. Confirm Next.js/PostCSS advisory option/proof.
9. Confirm registry credentials without printing secrets.
10. Confirm rollback/yank policy.
11. Confirm generated artifact cleanup.
12. Confirm release notes/tag policy.
13. Confirm package publish authorization when a registry upload is selected.

If a source-changing PR merges after step 3, the release SHA is no longer frozen
and final release-execution-time SHA proof must be regenerated.

## GO / NO-GO Status Matrix

Status definitions:

- `PASS`: fresh evidence exists and the gate passed.
- `FAIL`: fresh evidence exists and the gate failed.
- `BLOCKED`: the gate requires approval, credentials, tool availability,
  external proof, or a decision that is not present.
- `NOT RUN`: the gate has not executed in the current environment.
- `NO-GO`: release execution must not proceed.
- `APPROVED`: a human release owner explicitly approved the gate.
- `NOT APPROVED`: required human approval is absent.

The following actions remain blocked by this checklist:

- creating a tag;
- creating a GitHub Release;
- publishing to PyPI, TestPyPI, npm, GitHub Packages, or any package registry;
- running `twine upload`, `uv publish`, or `npm publish`;
- deploying a docs site, hosted demo, or any external service;
- changing `pyproject.toml`;
- bumping version metadata;
- mutating GitHub settings;
- posting bot comments;

## Execution-time Final SHA Proof

Final release proof must be generated after the release-candidate SHA is frozen.
It must not be produced by another source PR whose merge changes the candidate
SHA again.

The final proof packet must include exact release SHA, source ref, CI proof,
Public Raw Hygiene proof, public raw file proof, package smoke status,
advisory decision status, version decision, credential state without secrets,
rollback/yank policy, generated-artifact cleanup, approval fields, explicit
non-actions, and a final freshness check.

If the selected SHA moves after final proof generation, the proof is stale and
must be regenerated before execution.
