## Governance Decision

v0.19 does not approve package upload. It defines the approval, credential,
Trusted Publishing, smoke, README transition, and rollback/yank governance that
must be complete before a later release-execution packet can run.

Recommended release governance path:

1. Prefer PyPI Trusted Publishing via GitHub Actions for production PyPI.
2. Allow a manual PyPI API token only as an explicit fallback.
3. Keep upload execution separate from normal CI.
4. Require GitHub environment approval before the publish job can obtain an
   OIDC token.
5. Keep credential presence separate from release approval.
6. Keep README install conversion separate until production package proof and
   install smokes exist.

## Required Approval Flags

All flags below must be present in a later v0.20-or-newer execution packet
before any production PyPI upload command becomes eligible:

- `PRODUCTION_PYPI_RELEASE_APPROVED=true`
- `PYPI_UPLOAD_ALLOWED=true`
- `PACKAGE_PUBLISH_ALLOWED=true`
- `TARGET_REGISTRY=PyPI`
- `RELEASE_VERSION=0.10.0b0`

The required values above are approval-marker values only. They are not
credentials and do not contain secret material.

## Required Proof Before Production PyPI

A later production PyPI execution packet must record:

- fresh final SHA proof for the exact commit to publish;
- build artifact hashes for the exact wheel and sdist;
- `twine check` for the exact artifacts;
- production PyPI upload proof for `qa-z==0.10.0b0`;
- pip/pipx/uv install smoke from production PyPI;
- README transition proof after package availability is confirmed;
- rollback/yank stance and incident owner before execution.
