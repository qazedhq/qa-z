# v0.17 Multi-Agent Adapter Quality Pack

Date: 2026-05-27

## Goal

Make QA-Z repair handoffs clearer for multiple coding tools while keeping QA-Z
as the deterministic merge-safety layer.

## What Changed

- Added a shared repair adapter registry for `codex`, `claude`, `cursor`,
  `aider`, `openhands`, and `generic`.
- Normalized adapter Markdown around objective, evidence, files and risks,
  forbidden actions, required validation, final report format, and merge-safety
  boundaries.
- Kept `legacy` repair-prompt stdout available for the older generic prompt
  shape.
- Updated `repair-prompt`, guard repair artifacts, and repair-session handoffs
  to write all supported adapter Markdown files.
- Aligned GitHub Action adapter input validation with the expanded local
  adapter set.

## Product Value

Users can hand the same QA-Z evidence to Codex, Claude Code, Cursor, aider,
OpenHands, or a human reviewer without losing the safety contract. The coding
tool repairs; QA-Z keeps the merge decision tied to deterministic evidence and
post-repair verification.

## Boundaries

- No external AI agent API calls.
- No live model calls.
- No PyPI/TestPyPI upload.
- No `twine upload`.
- No tag, GitHub Release, or deploy.
- No version bump.
- No live PyPI install claim.
- No generated artifacts committed.

## Validation

Validation is recorded in the PR closeout. The focused adapter coverage is in
`tests/test_repair_handoff.py` and `tests/test_agent_adapter_docs.py`.
