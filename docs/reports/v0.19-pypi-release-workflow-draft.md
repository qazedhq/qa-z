# v0.19 PyPI Release Workflow Draft

Date: 2026-05-27

Draft only - not an active GitHub Actions workflow.

This is a future workflow outline for v0.20-or-newer execution review. It is a
document, not a file under `.github/workflows/`, and it does not grant publish
authority.

Do not copy this into `.github/workflows/` until v0.20 or a later approved
execution PR supplies the required approval flags, Trusted Publishing proof,
environment protection, and release-owner review.

## Future Workflow Outline

1. Validate requested version and final SHA.
2. Check out the exact final SHA.
3. build the wheel and sdist.
4. Record artifact names, sizes, and SHA-256 hashes.
5. Run `twine check` on the exact artifacts.
6. Wait for the protected `pypi-production` environment approval.
7. Run Trusted Publishing publish through the PyPI OIDC flow.
8. Capture production PyPI package URL/version proof.
9. Run pip install smoke from production PyPI.
10. Run pipx install smoke from production PyPI.
11. Run uv tool install smoke from production PyPI.
12. Open or prepare a README transition PR only after install smoke passes.

## Future Smoke Expectations

The production install smoke should prove the installed package can run:

- `qa-z --help`;
- `python -m qa_z --help`;
- `qa-z demo auth-bug --json`;
- `qa-z doctor --json`;
- guard/repair/verify flow with deterministic local fixture evidence.

## Required Workflow Permissions

Future publish job:

```yaml
permissions:
  contents: read
  id-token: write
```

Any broader permission requires separate release-owner justification and must
not be inherited from normal CI.

## Explicit Non-Actions

- This draft is not active.
- It does not upload to PyPI or TestPyPI.
- It does not run `twine upload`.
- It does not create a tag.
- It does not create a GitHub Release.
- It does not deploy.
- It does not create or read credentials.
- It does not change README install text.
