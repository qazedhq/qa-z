# v0.12 Profile Auto Detection

Date: 2026-05-27

## Scope

This slice improves first-time setup for `qa-z init`. It adds automatic profile
detection, dry-run explanation, generated `project.profile` metadata, and a
doctor warning when an explicit profile conflicts with local repository signals.

## Supported Signals

- Python: `pyproject.toml`, `requirements.txt`, `setup.py`, `setup.cfg`
- TypeScript: `package.json`, `tsconfig.json`
- Next.js: `next` in `package.json` dependencies or `next.config.*`
- Monorepo: `pnpm-workspace.yaml`, `turbo.json`, `apps/`, `packages/`, or
  multiple package manifests
- Existing config: `qa-z.yaml` remains source of truth and is not overwritten

## User Value

New users can run:

```bash
qa-z init --profile auto --dry-run
```

The dry run reports the selected profile, confidence, evidence files, activated
check assumptions, warnings, and next command without writing files. When the
choice looks right, users can run:

```bash
qa-z init --profile auto --with-agent-templates
```

## Doctor Integration

When `qa-z.yaml` includes `project.profile`, `qa-z doctor` compares that profile
with current repository signals. If the profile looks mismatched, doctor reports
a warning and suggests `qa-z init --profile auto --dry-run`.

This slice now builds on the v0.11 doctor environment diagnostics surface. The
profile mismatch warning appears alongside the runtime, install, resource,
tooling, and GitHub Actions diagnostics instead of replacing them.
