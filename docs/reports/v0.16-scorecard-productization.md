# v0.16 Scorecard Productization

## Purpose

Make QA-Z readiness and coverage easier to understand from one local command
without turning benchmark or release evidence into a marketing claim.

## What Changed

- Added `qa-z scorecard` with human, JSON, Markdown, and optional `--output`
  modes.
- The scorecard is read-only by default and layers over existing local signals
  instead of running benchmark, guard, Semgrep, or package-smoke workflows.
- The JSON payload has stable top-level fields for `status`, `version`,
  `dimensions`, `summary`, `next_actions`, and `warnings`.
- Dimensions report coarse statuses only: `ready`, `warning`, `blocked`,
  `not_configured`, or `unknown`.
- The command reports project config readiness, profile fit, fast checks,
  Semgrep/deep readiness, benchmark corpus readiness, repair prompt readiness,
  verify readiness, GitHub Action wiring, installed-package smoke evidence when
  applicable, and latest evidence freshness.
- Documentation now separates local `qa-z scorecard` from the OpenSSF Scorecard
  GitHub Actions workflow.

## Product Value

Users no longer need to inspect `qa-z.yaml`, latest run artifacts, benchmark
docs, GitHub workflow files, Semgrep installation state, and installed-package
smoke evidence separately just to answer "what is ready and what should I do
next?".

The command intentionally avoids fake numeric precision. A missing config is
`blocked`; missing Semgrep is `warning`; optional or non-applicable surfaces stay
`not_configured` or `unknown`.
