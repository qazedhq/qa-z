# QA-Z Reply Templates

Use these manually. Do not auto-reply.

## AI coding agents

The missing piece I keep running into is deterministic merge evidence after the agent changes code: what failed, what should be repaired, and whether the repair improved.

## Codex / Claude Code / Cursor

This is where agent workflows get interesting: not just generating the patch, but proving the patch is safe enough to merge.

## Semgrep / AppSec

AI coding makes shift-left security more important. Findings need to turn into repair instructions and verification evidence, not just reports.

## DevTools

The devtools problem is shifting from "can the agent produce code?" to "can the team trust the output enough to merge?"

## If someone asks what QA-Z is

QA-Z is a deterministic QA harness for AI-generated code. It turns agent changes into contracts, checks, repair prompts, and verification reports before merge.

https://github.com/qazedhq/qa-z
