# Posting Rules

QA-Z should behave like a careful open-source project account, not a growth bot.

## Required

- Human approval is required before every post, reply, follow, list creation, or
  profile change.
- Every technical claim must be traceable to the repository, alpha release,
  checked-in demo assets, or current docs.
- Keep alpha language visible when discussing v0.9.9-alpha.
- Use the validator before launch-week posting:

```bash
python marketing/x/scripts/validate_x_posts.py
```

## Prohibited

- No duplicate posts.
- No mass mentions.
- No auto-like behavior.
- No auto-follow behavior.
- No unsolicited auto-replies.
- No auto-DMs.
- No repeated requests for stars.
- No fabricated adoption numbers, user counts, companies, testimonials, or
  quotes.
- No package-registry, PyPI, TestPyPI, or GitHub Marketplace availability
  claims.

## Reply Standard

Reply only when QA-Z adds a concrete idea: deterministic gates, explicit QA
contracts, repair prompts, verification evidence, or a real demo. If the reply
would be generic promotion, skip it.
