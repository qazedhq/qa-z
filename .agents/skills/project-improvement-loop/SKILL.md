# Project improvement

Confirm repository identity, dirty work, and the requested outcome. Read AGENTS.md and only the current-truth references needed to choose the next change; use docs/agent/next-real-slices.md when the next step is unclear.

1. Choose a concrete user-flow, contract, verification, or cleanup improvement from repository evidence.
2. Make the smallest sufficient change and run its relevant checks. Use product-code-slice only when its extra guidance helps.
3. Update documentation only when its truth changed. Record useful evidence once in docs/agent/work-slice-ledger.md; do not duplicate the record across reports.
4. Continue until the requested outcome is complete or every independent authorized path is exhausted. Diagnose failures, resume checkpoints, and use equivalent approved paths; never weaken gates or fabricate external proof.

Run inline by default. Use actual subagents only when the user requests delegation and the harness allows it; do not simulate separate agents with repeated role passes.

For instructions or skills work explicitly requested by the user, a validated instruction change is a valid outcome. Otherwise move to product code once the operating model is usable. Do not repeatedly add scaffolding, force a Slice Card, reload unchanged documents, rerun passing checks without changed inputs, or expand a completed task into unrelated work.
